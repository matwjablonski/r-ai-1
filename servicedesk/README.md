# ServiceDesk

A self-contained training application for the AI-Powered Development workshop. The base application runs locally without Asana, GitLab, Figma, MCP, or other external accounts.

The [workshop guide](workshop/README.md) links all 24 exercises, identifies optional variants, and includes the local samples used for diagnosis, review, and CI analysis. Trainer solutions are kept outside this distributable application.

## Quick start

Docker with Compose v2 is the only requirement. The first build downloads images and dependencies.

```sh
docker compose up --build -d
docker compose ps
```

- Web application: http://localhost:3000
- API: http://localhost:8080
- OpenAPI JSON: http://localhost:8080/openapi/v1.json
- Health: http://localhost:8080/api/health

The source-controlled [OpenAPI YAML](openapi.yml) documents the workshop API, cookie session, CSRF flow, request bodies, and responses. The JSON endpoint above is generated by ASP.NET Core at runtime.

The first startup runs a single migration and seed step before the API becomes ready. If startup fails, inspect `docker compose logs migrate backend frontend db`.

## Lifecycle and data

```sh
docker compose ps
docker compose logs -f
docker compose down
docker compose up --build -d
```

A normal restart keeps the database volume and does not overwrite edits. To explicitly reset local project data, run `docker compose down -v` and then `docker compose up --build -d`. **`down -v` deletes the local database.**

Ports and the local database password can be overridden with the variables in `.env.example`; copying the file is optional. Web and API ports bind only to the host loopback address, and PostgreSQL is not exposed on the host by default.

## Development

For hot reload in containers:

```sh
docker compose -f compose.yaml -f compose.dev.yaml up --build
```

Native development is optional. Start the disposable database with `docker compose -f compose.test.yaml up -d db`, set `ConnectionStrings__ServiceDesk='Host=127.0.0.1;Port=15432;Database=servicedesk_test;Username=servicedesk;Password=test-only-password'`, then run `dotnet run --project backend -- --migrate` once and `dotnet run --project backend`. In `frontend`, use `npm ci` and `BACKEND_INTERNAL_URL=http://localhost:8080 npm run dev`. Local Node.js and the .NET SDK are required only for this optional route. This database is separate from the participant environment.

## Checks

```sh
docker compose -f compose.test.yaml run --build --rm backend-tests
docker compose -f compose.test.yaml run --build --rm frontend-checks
docker compose -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from frontend-e2e frontend-e2e
docker compose -f compose.test.yaml down
```

The test stack uses a separate PostgreSQL tmpfs database and does not change the participant's training database. See `docs/development/testing.md` for native commands. GitLab CI has separate frontend, backend, integration, E2E and image-build jobs. Its E2E/build jobs require a runner with privileged Docker-in-Docker support; no deployment job is included. When this directory remains inside the trainings monorepo, GitLab must explicitly include this `.gitlab-ci.yml` and set `SERVICEDESK_DIR` to its repository-relative path. The default `.` is for a standalone ServiceDesk repository.

## Documentation

- `docs/architecture/overview.md` — components and data flow
- `docs/domain/rules.md` — roles, transitions, and SLA
- `docs/adr/` — decisions and tradeoffs
- `docs/development/` — testing and diagnostics

This distribution is a functional starter. Notifications, automatic SLA escalation, and advanced reporting are deliberately outside its initial feature set.

Cookie sessions are HttpOnly and SameSite=Lax; write operations require an antiforgery token fetched from `/api/auth/csrf`. Demo credentials and the default database password are for trusted local training only. The first image build requires internet access; the running application does not call external services.
